# 团队 GitHub 使用指南

> 本指南教你如何通过终端（命令行）把自己的研究文件上传到项目的 GitHub 仓库中。请按顺序操作，第一次配置完成后，以后只需要重复"日常操作"部分即可。

------

## 一、准备工作

### 1. 注册 GitHub 账号

如果还没有账号，先去 [https://github.com](https://github.com/) 注册一个。

**请把你的 GitHub 用户名发给项目负责人（PM）**，PM 需要把你添加为仓库协作者（Collaborator），否则你没有权限上传代码。

### 2. 安装 Git

- **Windows**：下载安装 [Git for Windows](https://git-scm.com/download/win)，安装后会自带一个叫 "Git Bash" 的终端，后续操作都在这里进行。

- Mac：打开"终端"（Terminal），输入：

  ```bash
  git --version
  ```

  如果没安装过，系统会提示你安装 Xcode 命令行工具，按提示装即可。

- Linux

  ```bash
  sudo apt-get install git
  ```

安装完成后，验证一下：

```bash
git --version
```

出现版本号（如 `git version 2.43.0`）说明安装成功。

### 3. 配置你的身份信息

打开终端，输入以下命令（把姓名和邮箱换成你自己的，邮箱建议和 GitHub 账号邮箱一致）：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"
```

这一步只需要做一次，以后每次提交都会自动带上你的名字。

------

## 二、设置登录方式（重要，只需配置一次）

GitHub 现在不支持用密码登录，需要用 **Personal Access Token（个人访问令牌）** 或 **SSH 密钥**。这里推荐新手使用 **Token 方式**，比较简单。

### 方法：使用 Personal Access Token

1. 登录 GitHub，点击右上角头像 → **Settings**
2. 左侧菜单拉到最下面，点击 **Developer settings**
3. 点击 **Personal access tokens** → **Tokens (classic)**
4. 点击 **Generate new token (classic)**
5. 给它起个名字（比如 "我的电脑"），勾选权限 **repo**（这一项会自动勾选所有子项）
6. 拉到最下面点击 **Generate token**
7. **立刻复制这串 token 并保存到安全的地方**（比如密码管理器），页面刷新后就再也看不到了

之后你在终端第一次连接仓库时，系统会要求你输入用户名和密码，这时候：

- 用户名：填你的 GitHub 用户名
- 密码：**粘贴刚才复制的 token**（不是你的 GitHub 登录密码）

系统通常会记住这个 token，不用每次都输入。

------

## 三、第一次获取项目仓库（只需一次）

假设 PM 已经把仓库地址发给你了，形式类似：

```
https://github.com/团队名/项目名.git
```

1. 在电脑上找一个你想存放项目的文件夹位置，打开终端，`cd` 进入该文件夹。例如：

   ```bash
   cd Desktop
   ```

2. 执行"克隆"命令，把仓库下载到本地：

   ```bash
   git clone https://github.com/团队名/项目名.git
   ```

3. 完成后会出现一个新文件夹（和项目名同名），进入它：

   ```bash
   cd 项目名
   ```

以后你所有的研究文件、代码、文档，都放在这个文件夹（或它的子文件夹）里。

------

## 四、日常操作：把你的研究上传到 GitHub

这是你以后**每次更新完成果**都要重复的流程，一共 5 步。

### 第 1 步：进入项目文件夹

```bash
cd 项目名
```

### 第 2 步：先拉取最新内容（避免冲突）

在开始工作前，先确保自己的本地代码是最新的，尤其是团队协作时：

```bash
git pull
```

### 第 3 步：把你的文件放进这个文件夹

把你写好的论文、数据、代码等文件，直接复制/保存到这个项目文件夹（或子文件夹）里。

### 第 4 步：查看修改了哪些内容（可选，但推荐）

```bash
git status
```

这会列出你新增或修改的文件，用不同颜色标出。

### 第 5 步：提交并上传，一共三条命令

```bash
git add .
git commit -m "简单描述这次更新的内容，比如：上传第三章实验数据"
git push
```

逐条解释：

- `git add .` —— 把所有改动"打包"准备提交（`.` 代表当前文件夹下所有改动）
- `git commit -m "..."` —— 给这次改动写一句说明，方便以后查看历史记录
- `git push` —— 真正把改动上传到 GitHub 网站上

**上传成功后，你可以打开 GitHub 网页刷新看看，就能看到你的文件了。**

## 五、常见问题

### Q1: `git push` 时提示需要输入用户名密码

- 用户名填 GitHub 用户名
- 密码填第二部分生成的 **token**（不是登录密码）

### Q2: 提示 `Permission denied` 或 `403`

说明你还没有这个仓库的权限，联系 PM 把你加为协作者（Collaborator）。

### Q3: `git pull` 或 `git push` 提示冲突（conflict）

这通常发生在两个人同时修改了同一个文件的同一部分。这种情况建议**立刻联系 PM 或修改过该文件的同事**，一起确认应该保留哪部分内容，避免自己随意覆盖别人的工作。

### Q4: 不小心把不该传的文件（比如大数据集、密码文件）传上去了

先联系 PM，不要自己尝试删除历史记录，操作不当可能让整个仓库出问题。

### Q5: 我只是想看看现在项目里有什么，不想改动

直接用文件管理器打开本地的项目文件夹查看即可，或者去 GitHub 网页上看。

------

## 六、快速命令速查表

| 命令                   | 作用                     |
| ---------------------- | ------------------------ |
| `git clone 仓库地址`   | 第一次下载项目到本地     |
| `git pull`             | 拉取最新内容             |
| `git status`           | 查看当前改动了哪些文件   |
| `git add .`            | 把所有改动加入待提交列表 |
| `git commit -m "说明"` | 提交改动，附带说明       |
| `git push`             | 上传到 GitHub            |

------

## 七、提醒

> **每次开始工作前先 `git pull`，每次工作结束后记得 `git add . / git commit / git push` 三连，养成习惯就不会丢数据。**

如果操作中遇到任何报错信息看不懂，**直接截图发给 PM**，不要自己瞎删文件或强制覆盖，很多问题是可以简单解决的。
